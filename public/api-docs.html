Scholarship Scout API Reference

Machine-readable contract: OpenAPI 3.1 JSON. Automated discovery entry point: RFC 9727 API catalog.

This reference documents the two deployed application-owned Edge Function APIs. Supabase-managed Auth and database REST interfaces are operated by Supabase and are outside this application-owned OpenAPI document.

Scholarship discovery

POST https://wjrwvempgjvoxlioodse.supabase.co/functions/v1/scholarship-discover

Public, rate-limited discovery. A signed-in Supabase user is not required. Include the project's browser-safe publishable key in the apikey header.

Request

{
  "profile": {
    "state": "TX",
    "graduationYear": 2027
  },
  "categories": ["local", "academic"]
}

state must be a valid US state or territory abbreviation. graduationYear must be an integer from the current UTC year through nine years ahead. Select one to four distinct categories:

local, school_resources, regional, state, academic, humanities, leadership, community_service, language, employment, arts, incoming_college, national, general.

Response

HTTP 200 returns results, count, provider, warnings, and a search summary. A result is an unverified_lead. It is not sponsor verification, eligibility confirmation, or an application submission.

HTTP 400 indicates invalid filters; 413 indicates a request body over 8 KiB; 415 indicates a non-JSON Content-Type; 429 indicates rate limiting and includes Retry-After; 502 indicates all upstream searches failed; 503 indicates unavailable gateway or rate-limit configuration.

Privacy boundary: send only state, graduation year, and selected category IDs. Do not send a student's name, school, grades, class rank, test scores, activities, contact details, essays, or full profile. Discovery leads must be checked at the official sponsor source.

Account deletion

POST https://wjrwvempgjvoxlioodse.supabase.co/functions/v1/account-delete

Authenticated, destructive operation. Include both the project publishable key in apikey and the currently signed-in user's Supabase access token as Authorization: Bearer ....

Request

{
  "confirmation": "DELETE_MY_ACCOUNT"
}

The server verifies the bearer token and derives the account ID from that verified user. The client cannot supply another user's ID. The server revokes refresh-token sessions before deleting the Auth user.

Response and safety

HTTP 200 returns {"success": true}. A 400 response means confirmation did not match; 401 means the session is missing or invalid; 403 means the request origin is not allowed; 413 means the body exceeded 2 KiB; 500 or 502 means deletion or session revocation could not be completed; 503 means required server configuration is unavailable.

Irreversible: only call this endpoint after the account owner has deliberately confirmed deletion. Refresh-token sessions are revoked globally. Already-issued access-token JWTs may remain valid until their expiry, but cannot be refreshed.

Unavailable endpoints

The sponsor-verification function is an undeployed, disabled placeholder and is intentionally not listed as an available API. There is no public health endpoint for either listed function, so the catalog does not publish a status relation.
